## 起因
我在做小工具时，发现多端同步对于日常使用来说非常重要。在电脑上记过的，在手机上往往也会想看，特别是小工具们的设计目的就是轻量化和便捷。但一提到“同步”，常规方案就来了：买服务器、租数据库、上云服务。我只是想存几个文本文件，不想为这个养一台机器。

但我很快想通了：
> GitHub私人仓库本身就是个带版本历史的云端文件存储，**而且免费**，我缺的只是一个能读写它的界面。

## 方案
那么一个究极省钱的方案就这样出现了：*把数据层和界面层拆给两个GitHub仓库*
- 数据层：一个 GitHub 私人仓库，里面就是普通的文件。
- 界面层：一个纯静态网页，托管在 GitHub Pages 上，用默认的 github.io 域名。
- 认证：去 GitHub 生成一个细粒度令牌，填进网页里，网页利用令牌直接调取 GitHub API 读写私人仓库。


**最重要的是它一分钱都不用花！！！**
- 仓库免费、托管免费、域名免费、API 免费。我不需要为“同步”这件事花一分钱，也不需要维护任何机器。
- 加上我没有后端，所以没有服务端可被攻击。 没有服务器代码，就没有 RCE、没有注入、没有会话劫持、没有运维失误。如果想通过“攻击我的服务器”拿数据，会发现**我根本没有服务器。**
- 最后，数据隔离是天然的。 仓库是私人的，没我的令牌，他人无法访问我的仓库；别人有自己的令牌，也可以访问自己的专属仓库。*（你是说我们一毛没花直接有用户系统了吗老师。。。）*

其实我一直在竭尽全力地避开服务器，第一是真的很烧钱，我的私人骰子活着就在烧钱，而且国内服务器还得备案，第二就是，虽然我是学某需要运用统计和代码的神秘专业的，但我亲爱的母校……居然没开过SQL相关课程，我只会在本地取个数然后开始跑模型，所以我真不太会这个，盲目搞后端容易变成裸奔活靶子（）
## 具体怎么办
思考完上述问题，我们就可以去蹭GitHub了。这里我只给怎么搞定令牌的教程，因为这是面向小工具用户的必要教程~如果是专业人士肯定比我懂得多，所以我只提醒纯萌新小白具体怎么办就行
1. 有一个自己的GitHub账号
2. 新建一个私人仓库，Choose visibility 时选择private就ok，其他的保持默认，名字和介绍随便填
3. 接着返回主页，点击右上角你的头像，找到setting，点击后拉到底找到developer setting
4. 在personal access token的Fine-grained token里generate new token
5. 名字和介绍随便填，Expiration根据你想保证的token的有效期来选，Repository access选择Only select repositories，并选中你创建的私人仓库
6. add permission 选择 Contents，改为read and write，然后generate token
7. 把令牌记好
## 它的边界
这套方案适合的是个人自用的小工具，追求的是零成本、无后端、多端同步、数据归使用者所有。

在这个定位下，我不觉得它是“妥协后的选择”。它是一个在特定场景下很干净的代餐方案。至于账号安全、令牌泄露这些事，那是所有需要在浏览器里处理凭证的方案共同面对的问题，不是这套东西独有的缺陷。
